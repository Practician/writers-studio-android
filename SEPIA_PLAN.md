## 1. Диагноз по данным

### 1.1 Внешний детектор vs локальный аудит

| Метрика | Значение |
|---|---|
| Внешний отчёт (22 сегмента) | **AI 22, LIKELY_AI 0, HUMAN 0** |
| Локальный аудит | 17 → 17 за 5 проходов, `gate не пройден` |
| Прошлый прогон (из комментария в `chapterGenerate.ts:2703`) | локально 13/100 при 22/22 «AI» |

Вывод: очеловечивание **не снижает то, что ловит внешний детектор**, а локальная метрика
слепа к этому. Это не баг одного промпта, а рассинтрон измерителей. Плюс отчёт сам по себе
содержит tell, который наш аудит не меряет: 22 сегмента **по 146–182 слова** — равномерная
нарезка, характерная для gemini-lite (это же зафиксировано в комментарии
`humanStyleEnhanced.ts:838`).

### 1.2 Экономика прогона (журнал)

- 69 запросов на одну главу: `sepia enhanced-фазы ×8`, `литературный проход ×4`.
- Отбраковки: OpenRouter `HTTP 402` (нет кредитов), `openrouter/free` → ответ 0 символов /
  `завершение length`, Gemini `HTTP 503` ротацией по 4 модели подряд, пустые ответы.
- Куски 6453 / 3016 / 3229 символов — блоки обрезаны и по логике
  `chapterGenerate.ts:~760` (`candidate.length < chunk.length * 0.67`) **выбрасываются целиком**.

### 1.3 Патч

`gemini-keys-fix.patch` **не применён** в рабочей копии (0 вхождений `GEMINI_STICKY_MS`,
`geminiContentBlocked`). Пока он не применён, любые улучшения промптов тонут в обрезанных
и пустых ответах — это пункт 0 плана.

## 3. План работ

### Этап 0 — инфраструктура (без неё остальное бессмысленно)

1. Применить `gemini-keys-fix.patch` (`PHASE_MODEL_ROUTING=false`, `GEMINI_STICKY_MS`,
   учёт `geminiContentBlocked`), прогнать `tests/geminiKeyOrder.test.ts`.
2. Обрезанный ответ (`finishReason=length` / `len < 0.67×`) не выбрасывать, а **дотягивать**
   продолжением (одна докомплектующая по запросу) — иначе 8 sepia-фаз из журнала частично
   превращаются в пустые.
3. Считать стоимость: сейчас 69 запросов на главу. После патча — замерить и зафиксировать
   бюджет (цель: ≤ 25 запросов на главу).

### Этап 1 — диагностический проход по рубрике sepia (новый модуль)

`server/sepiaRubric.ts`:

- 5 групп из `rubric.md` (A — тематическая детерминизм, B — сенсорика/тело,
  C — структурная структурированность, D — позитивные маркеры, E — время и 다양ность),
  **каждая группа — отдельный запрос**, с цитатой на каждый сигнал (`no quote — no signal`),
  с пометкой `n/a` и отдельной строкой **over-correction** (значение у края, противоположного
  ИИ-направлению → это новый отпечаток humanizer'а, а не «человеческий» признак).
- На выходе — **список дефектов, отсортированный по слоям (самый глубокий первый)** —
  это stage 1, которого сейчас нет вовсе.
- Читать группы раздельно обязательно: измерение sepia даёт span precision 0.13–0.16 при
  сплошном чтении — модель, оценивающая всё сразу, слепнет на 1–2 признаках.

### Этап 2 — калибровка приёмов (самое дешёвое и, судя по 22/22, самое влияющее)

- Вынести выбор приёмов **со сцены на главу**: один раз перед генерацией выбрать
  **3–5 приёмов + 1 rarity-move** на всю главу, раздать карту сценам в beat-plan
  (`buildBeatPlanPrompt`, `chapterGenerate.ts:1210`).
- `SCENE_SEPIA_MOVES` (`:1103`) перестать применять на каждой сцене: каждый приём обслуживает
  максимум 1–2 сцены на главу, остальным сценам — «оставить как есть».
- `NARRATIVE_ARCHITECTURE_CHECKLIST` / `DISCOURSE_FLOW_CHECKLIST` / `HUMAN_POSITIVE_MARKERS_CHECKLIST`
  не накладывать все сразу — это уже 13 пунктов поверх 8 пунктов сцены = 21 директива на главу.
- Добавить **проверку на перекоррекцию** в отчёт: сколько приёмов применено на главу,
  сколько «осталось slack».

### Этап 3 — выстроить слои в правильном порядке (refactor по sepia)

Текущий порядок фаз заменить на слойную хирургию:

1. **architecture-pass** — на **всю главу** (один запрос на главу либо чанки по границам сцен,
   не 7000 символов): правка развязки, причинно-следственных цепочек, «герой выбрал → принял →
   вырос», экфразиса. Опирается на дефект-лист этапа 1.
2. **discourse-pass** — по сценам/абзацам: линейная цепочка «что случилось → почему → что это
   значит», текстуры соседних сцен, завершение абзацев репликой, списки по три.
3. **style-pass** — последним, чанками 7000: лексика, синтаксические шаблоны, штампы.
   (`chapterGenerate.ts:636` — оставить только для этого слоя.)

Правило «самое глубокое первым» прямо из sepia: paraphrasing без списка дефектов усиливает
отпечатки. Сейчас мы шлифуем поверхность архитектурно неисправной главы.

### Этап 4 — гейт, который коррелирует с внешним детектором

- Оставить regex-скор как один из сигналов, но добавить структурные метрики, которые как раз
  ловит внешний детектор: **CV длины сегментов/абзацев** (сейчас 146–182 слова — почти
  константа), opener-цепочки, доля равномерных реплик, TTR, пассив, connector diversity —
  часть уже есть в `runMultiDetectorGate` (`humanStyleEnhanced.ts:679`), но не свёрнута в
  единое решение вместе с рубрикой.
- **Калибровка на реальных отчётах**: у нас есть негатив (`result_*.json`, 22/22 AI).
  Нужен позитив — 2–3 человеческие главы (см. `~/storage/downloads/книги`, авторские тексты),
  прогнать через тот же детектор и подогнать пороги так, чтобы человеческие тексты проходили.
  Без этого «17» ничего не значит.
- Честность отчёта: при `gatePassed=false` либо ретраить, либо явно показывать в UI
  «внешний детектор не прогнан» (сейчас `detectorHypothesised: true` есть, но счёт
  «Естественность 83/100» выглядит как успех).

### Этап 5 — прямые правила sepia в промптах

1. **Deletion beats addition**: в фазах правки запретить рост текста (cap 1.0× вместо 1.35),
   считать доли replace/delete/insert и репортить их; repair-правки (разбор трудного
   предложения) не считать приростом.
2. **Never invent specifics**: конкретика в мире должна быть настоящей (марка, номер, цена,
   книга) — уже частично в `SCENE_SEPIA_MOVES`, оформить как hard guardrail во всех промптах.
3. **Protected ranges**: реплики и цитаты не регуляризовать, не «выравнивать» — отдельный
   запрет в style-pass.
4. **Whitelists**: не флагать чистую грамматику и формальный регистр — иначе аудит вычёркивает
   нормальные места и провоцирует перекоррекцию.
5. **Model identity**: таблица версий → `operative | prior | none` (правило sepia: Gemini 3.5/3.8
   вне тега «3 and 3.1» → prior); добавить fingerprint для `openai/gpt-oss-120b` и
   `deepseek-v3.2` (сейчас пусто, а по журналу это основные исполнители).
6. **Синхронизировать два набора правил**: `humanStyleDirectives()` (`humanStyle.ts:758`,
   20 правил) и `humanizeDirective` (`directLlmClient.ts:1377`) расходятся — это два разных
   голоса в одном конвейере.
7. **Voice fit**: подключить `authorPipeline` (профиль автора) к генерации главы — правила
   sepia требуют редактировать *в сторону профиля автора*, а не в сторону абстрактного
   «человеческого».

### Этап 6 — измеримость (иначе план не проверить)

- Регрессионный набор: 22 сегмента из `result_2026-09-29T11-06-30.json` (негатив) +
  человеческие главы (позитив).
- Метрики на каждый прогон: доля `HUMAN` у внешнего детектора, движение групп рубрики,
  число приёмов на главу, доля replace/delete/insert, число запросов на главу.
- `docs/SEPIA.md` — таблица «правило sepia → файл:строка», которой в репозитории сейчас нет:
  слово «sepia» встречается только в 4 местах `chapterGenerate.ts`.
