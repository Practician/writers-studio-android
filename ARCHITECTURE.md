# Архитектура автономного Android APK

## Принцип

Writers Studio Android не использует собственный Node/Express сервер в runtime. Vite bundle копируется внутрь APK через Capacitor, а встроенный direct LLM client обращается по HTTPS прямо к выбранному провайдеру. Пользователь вводит собственный API-ключ после установки приложения.

| Внутри APK | Вне APK |
|---|---|
| React UI, рукописи, библиотека книги, паспорт автора, prompt builders, локальный агент, direct LLM adapters | Только HTTPS API Gemini, OpenRouter, Groq или NVIDIA |

API-ключи не включаются в исходный код, GitHub Actions, GitHub Secrets или APK artifact. На Android они сохраняются через secure storage plugin; резервное копирование приложения выключено в manifest.

## Роль агента

Агент находится внутри раздела **«Текст»**, после предполётной проверки главы. Он не является отдельной верхней вкладкой и не дублирует быстрые инструменты.

| Быстрые действия «Текста» | Редакторский агент |
|---|---|
| Написать новый материал | Не создаёт главу с нуля |
| Продолжить сцену | Не продолжает текст по одной команде |
| Отредактировать выделение или главу | Не выполняет одиночную точечную правку |
| Проверить главу | Даёт быстрый диагностический результат |
| — | Собирает контекст → диагностирует → готовит бережную версию → проводит финальный аудит → возвращает редакторское письмо |

Вставка подготовленной версии всегда выполняется автором вручную. Агент не заменяет рукопись автоматически.

## Сборка

GitHub Actions запускается после push в `master`/`main`: TypeScript → тесты → Vite build → Capacitor sync → APK. Пока постоянная подпись не настроена, workflow явно публикует debug APK для тестирования.

Для обычных обновлений без удаления приложения workflow использует подписанную release-сборку. В repository secrets добавляются только `KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD` и `RELEASE_KEY_ALIAS`; пароль ключа берётся равным паролю keystore, как в исходной схеме Bookstore. Keystore расшифровывается только на время CI и исключён из Git. `APP_VERSION_CODE` получает номер запуска GitHub Actions, поэтому каждая release-сборка имеет более высокий Android versionCode.

LLM API-ключи пользователей никогда не становятся CI secrets и не входят в APK.
